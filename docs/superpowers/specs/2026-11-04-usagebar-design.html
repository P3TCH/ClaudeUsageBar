UsageBar

Design spec · 2026-11-04 · macOS menu bar app for Claude Code and Codex usage limits

1. Goal

A native Swift macOS app that lives in the menu bar and shows how much of your Claude Code and Codex (ChatGPT) usage limits you have used, so you can check at a glance without opening a terminal.

  • Sign in to each service with OAuth (PKCE) in the browser.
  • Claude: session (5-hour) use, weekly use (all models) and weekly Fable use, plus any other model-scoped weekly rows the server sends.
  • Codex: session (5-hour) use and weekly use.
  • The user chooses which values appear in the menu bar itself. The popover always shows everything.

Out of scope (this round)

Launch at login, notifications near a limit, multiple accounts per service.

2. Endpoints (verified against the local CLIs)

Both usage endpoints are undocumented. They are the same ones the official CLIs call (Claude Code 2.1.318, Codex 0.166.0), so they can change without notice. Parsers must tolerate missing fields.

Claude

TokenPOST https://platform.claude.com/v1/oauth/token, JSON body. Exchange: grant_type=authorization_code, code, redirect_uri, client_id, code_verifier, state. Refresh: grant_type=refresh_token, refresh_token, client_id.
UsageGET https://api.anthropic.com/api/oauth/usage, headers Authorization: Bearer, anthropic-beta: oauth-2025-04-20

Usage response: the top-level five_hour / seven_day objects carry utilization (0–100) and resets_at (ISO 8601). Newer responses also carry limits[] rows with kind (session, weekly_all, weekly_scoped), percent, resets_at and scope.model.display_name. The weekly Fable limit is the weekly_scoped row whose display name is “Fable”. Parse the top-level keys first, then let limits[] rows override them.

Usage response: plan_type plus rate_limit.primary_window / secondary_window, each with used_percent, limit_window_seconds, reset_at (Unix seconds) or reset_after_seconds. Either window can be null, and some plans send only a weekly primary window, so a window is classified by length: ≤ 24 h is the session, longer is weekly.

3. Architecture

Swift Package, macOS 14+, no third-party dependencies. Two targets:

  • UsageBarCore (library, unit-tested): models, parsers, PKCE, JWT decoding, label formatting, OAuth flows, usage clients, Keychain storage, loopback server.
  • UsageBar (executable): SwiftUI MenuBarExtra with .window style, the observable store and the views.

scripts/build-app.sh builds a release binary, wraps it in build/UsageBar.app with an Info.plist that sets LSUIElement (no Dock icon), and ad-hoc signs it.

Components

UnitResponsibility
ModelsProvider, MetricKind (session / weekly / scoped(name)), UsageMetric, UsageSnapshot, StoredToken, UsageError
PKCEVerifier, S256 challenge, state
JWTDecode a JWT payload (no signature check; the token came straight from the issuer over TLS)
LoopbackServerOne-shot HTTP listener bound to the loopback interface; returns the callback query parameters
OAuthFlowStart the listener, open the browser, wait for the redirect (5-minute timeout), check state
ClaudeService / CodexServiceSign in, refresh, fetch usage; each conforms to UsageService
ClaudeUsageParser / CodexUsageParserPure functions: JSON → [UsageMetric]
KeychainStoreOne generic-password item per provider, JSON-encoded StoredToken
MenuBarItem + MenuBarLabelThe selectable items and the label text built from the current snapshots
UsageStore (app)Holds per-provider state, polls every 5 minutes, refreshes tokens when they are within 60 s of expiry or after a 401
Views (app)Menu bar label, popover with a card per provider (bars, percent, reset time), inline settings panel

4. Data flow

Sign in:  button → OAuthFlow (loopback + browser) → code → token exchange → KeychainStore → fetch usage
Poll:     timer (5 min) / Refresh button → token valid? (refresh if needed) → GET usage → parser → snapshot
Display:  snapshots + selected MenuBarItems → MenuBarLabel text;  snapshots → popover cards

5. Error handling

CaseBehaviour
401 from usageRefresh once and retry. If it still fails, mark the provider “Sign in again”.
Refresh rejectedDelete the stored token and show “Sign in again”.
429 / network errorKeep the last snapshot, show the error and the time of the last good fetch, retry on the next cycle.
Unexpected JSON“Unknown response” on that card only; the other provider keeps working.
Port 1455 in useMessage: close any running codex login and try again.
State mismatch / timeout / user deniesSign-in fails with a message; nothing is stored.

6. Testing

  • swift test (Swift Testing): PKCE format and challenge vector, JWT decode, Claude parser (top-level only; with limits[] including Fable), Codex parser (both windows; weekly-only primary; null windows), menu bar label formatting, reset-time formatting.
  • Manual end-to-end: build the .app, sign in to both services in the browser, compare numbers with /usage in Claude Code and /status in Codex.
